# Fix the defect in the TVM-onnx frontend converter "Pad"

## 1. Root cause of the defect (attribution)
Root cause (LLM attribution + manual confirmation): the mode whitelist of
Pad._impl_v2 / _impl_v11 only contains ["constant","edge","reflect"]; a legal
mode="wrap" from opset 18+ raises OpAttributeInvalid ("Value wrap in attribute 'mode'
is invalid"); and v11 does not handle the opset-18 axes input (it ignores the 4th
input and treats pads as full-rank -> dimension-mismatch ValueError).
onnx.checker / onnx.reference / onnxruntime all accept and correctly run wrap and axes.
wrap is cyclic padding (topi.nn.circular_pad already exists). The already-supported
shapes behave correctly and must not change.

## 3. Key documentation information (only what is needed for the fix)
ONNX Pad specification (opsets 2/11/13/18/19):
- mode attribute: "constant" | "reflect" | "edge" | "wrap". Among these, "wrap"
  (cyclic/toroidal padding) is new in opset 18; topi.nn.circular_pad already implements
  circular padding.
- opset 18+ adds the optional axes input (the 4th input): pads only the specified
  dimensions; pads length = 2 * len(axes); when axes is not provided, pads length = 2 * rank.
- pads ordering: [x1_begin, x2_begin, ..., x1_end, x2_end, ...].
- opset 11+ input form: (data, pads[, constant_value[, axes]]).
