Root cause (LLM attribution + manual confirmation): PRelu._impl_v1 only accepts slopes
that are all-ones, 1-D, or same-rank with a single non-broadcast axis; a legal slope
with multiple non-broadcast dims of the same rank (including a slope with the same
shape as X) directly raises ValueError "Invalid PRelu slope shape (multiple
non-broadcast dims)"; lower-rank/scalar slopes are also rejected.
However, the ONNX spec allows arbitrary unidirectional broadcasting; onnxruntime /
onnx.reference both accept and correctly run these — this is a legal model being
rejected by the frontend (a coverage gap), not a numerical error in already-supported
shapes.
The already-supported shapes (all-ones / 1-D / same-rank single non-broadcast axis)
behave correctly; the fix must not change this behavior.
