Root cause (LLM attribution + manual confirmation): Flatten._impl_v13 does not
validate the axis range and does not normalize negative axes. The code slices
data_shape[0:axis] directly, and Python slicing silently clamps out-of-range indices:
- An out-of-range axis (e.g., rank-3 input with axis=5) silently produces the wrong
  shape (24,1) instead of raising an error;
- A negative out-of-range axis (e.g., axis=-4) silently produces (1,24).
This violates the ONNX spec axis in [-r, r]; onnxruntime raises ShapeInferenceError
for out-of-range axes.
Legal axes (including legal negative axes) currently behave correctly; the fix must
not change this behavior.
